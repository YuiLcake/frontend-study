第 25 天：作用域、闭包、this

今天没有一个新方法，全部是在讲"变量从哪来"。这一课慢一点看。

一、作用域链：变量是"往上找"的

const g = "全局";

function outer() {
  const o = "外层";
  function inner() {
    const i = "内层";
    console.log(g, o, i);
  }
  inner();
}
全局 外层 内层

规则：在当前作用域找不到，就往上一层找，一直到全局。

function outer() {
  const o = "外层";
  function inner() {
    const i = "内层";
  }
  console.log(i);     // ✗ 找不到
}
ReferenceError: i is not defined

只能往上找，不能往下找。外层拿不到内层的变量——这就是"函数是一个封闭的房间"。

关键：作用域在"定义时"就定了

这叫词法作用域（lexical scope）：函数在哪里定义，它的作用域就是哪里，跟在哪里调用没关系。

这条听起来抽象，但它是闭包的全部前提。

二、闭包：函数会"记住"它出生时的环境

看这段代码，先猜结果：

function makeCounter() {
  let count = 0;
  return function () {
    count = count + 1;
    return count;
  };
}

const c1 = makeCounter();
console.log(c1(), c1(), c1());   // ?
1 2 3
为什么 count 没被清掉？
一般函数执行结束后，里面的局部变量会被销毁。
但这里 makeCounter 返回的那个函数还在用 count， 所以 JS 不会销毁它——这个内部函数"记住"了它出生时的环境。 这就是闭包（closure）。

换成一个比喻：函数出生时，把当时周围的变量装进背包带走了。之后不管走到哪被调用，背包里的东西都还在。

每次调用都是新的背包

const c1 = makeCounter();
const c2 = makeCounter();

c1(); c1();          // c1 的 count 变成 2
console.log(c2());   // 1   ← c2 是独立的另一个背包
1

这一点很重要：闭包不是共享的，每调用一次外层函数，就产生一个新的独立环境。

三、闭包到底有什么用

用途 1：计数器 / 状态保存

上面的 makeCounter。每次调用都能延续上一次的状态，但外面改不了 count。

用途 2：私有变量

function createAccount(initial) {
  let balance = initial;
  return {
    deposit(n) { balance += n; return balance; },
    getBalance() { return balance; },
  };
}

const acc = createAccount(100);
acc.deposit(50);
console.log(acc.getBalance());    // 150
console.log(acc.balance);         // undefined ← 外面直接拿不到
150 undefined

这是 JS 里做"私有属性"的传统办法——变量藏在函数里，只通过返回的方法访问。 外面没法直接改 balance，只能走 deposit。

用途 3：函数工厂（用一个函数造一批类似的函数）

function makeGreeter(prefix) {
  return function (name) {
    return `${prefix}，${name}`;
  };
}

const sayHi = makeGreeter("你好");
const sayBye = makeGreeter("再见");

sayHi("熙熙");      // "你好，熙熙"
sayBye("熙熙");     // "再见，熙熙"

用途 4：事件回调里保存状态（后面会天天遇到）

function bindCounter(button) {
  let clicks = 0;                    // 每个按钮自己的计数
  button.addEventListener("click", () => {
    clicks++;
    console.log(`点了 ${clicks} 次`);
  });
}

这个模式你会写几十遍：外面定义一个变量，回调里读写它——那就是闭包在工作。

四、经典面试题：var 在循环里

先猜结果：

for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);
  }, 100);
}
3 3 3

再猜这个：

for (let j = 0; j < 3; j++) {
  setTimeout(function () {
    console.log(j);
  }, 100);
}
0 1 2
为什么 var 全是 3：
var 只有一个变量 i，整个循环共用。
三个回调都是闭包，都记着同一个 i。
100ms 后回调执行时，循环早跑完了，i 已经是 3。

为什么 let 是 0 1 2：
let 在每次循环里都创建一个新的 j。
三个回调各自记住了自己那一轮的 j，互不干扰。

这就是为什么复习时我一直强调"for 循环的计数器要写 let"——不只是"要声明变量"， 而是 let 和 var 在循环里的行为完全不同。

五、this：谁调用我，我就是谁

先记住一句话：this 在运行时才确定，看的是"怎么调用的"。

规则 1：通过对象调用 → this 是这个对象

const user = {
  name: "熙熙",
  sayHi() {
    console.log(this.name);
  },
};

user.sayHi();      // "熙熙"     ← 点是 user. 调的
熙熙

规则 2：单独拿出来调用 → this 丢了

const fn = user.sayHi;     // 只是把函数摘出来
fn();                      // this 不再指向 user
undefined
这是前端最常见的 bug 之一。
const fn = user.sayHi 只是把函数本身拿走，没有带走 user。
再单独调用时，就没有"点号前面的对象"了，this 变成 undefined（严格模式）。

修法：user.sayHi.bind(user)，或者用箭头函数包一层。

规则 3：箭头函数没有自己的 this

const user = {
  name: "熙熙",
  sayHi() { console.log(this.name); },          // 普通方法：this = user
  sayHiArrow: () => { console.log(this.name); } // 箭头：this 来自外层
};

user.sayHi();        // "熙熙"
user.sayHiArrow();   // undefined  ← 不是 user
箭头函数不绑定 this，它用的是"定义它时外层的 this"。
所以：对象的方法用普通函数写，回调用箭头函数写。
这是最实用的判断标准。

规则速查

调用方式this 指向
user.sayHi()user
fn()（单独调用）undefined（严格模式）/ 全局对象
fn.call(obj) / fn.apply(obj)obj（手动指定）
fn.bind(obj)()obj（永久绑定）
箭头函数不看调用方式，看定义时的外层
new Foo()新创建的那个对象（后面讲 class 再说）

六、四个常见错误

① 以为函数执行完变量就没了

function make() { let x = 1; return () => x; }
const f = make();
console.log(f());      // 1  ← x 还在，因为 f 闭包着它
不报错，但预期会错（有人以为会报 not defined）

② 循环里用 var，回调拿到同一个变量

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);   // 3 3 3
}
不报错，结果和预期不同

③ 把对象方法单独赋值后调用

const fn = user.sayHi;
fn();          // this 丢失
不报错，this 是 undefined，读属性时报 Cannot read properties of undefined

④ 在对象里用箭头函数当方法

const user = {
  name: "熙熙",
  sayHi: () => console.log(this.name),   // undefined
};
不报错，this 不是 user
