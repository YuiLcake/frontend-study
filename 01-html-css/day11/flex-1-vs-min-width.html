flex: 1 和 min-width: 0 各管什么

同一个结构，只改 .content 的规则，看四种结果。

对照组：内容短，容器放得下

这里什么都没加，看起来完全正常——因为根本用不上。

frontend-study
Star
.content { }              /* 默认 flex: 0 1 auto */
.star    { flex: none; }

情况 1：内容超长，什么也不加

内容是一长串不带空格的字符（真实场景：长 URL、长英文单词、没有空格的中文长串）。 蓝色块顶破了黑框，橙色 Star 被挤到框外面去。

http://localhost:8123/01-html-css/day11/challenge.html
Star
.content { }              /* flex: 0 1 auto，min-width: auto */
.star    { flex: none; }
为什么缩不下来？
flex 项目默认 min-width: auto，意思是"我最小不能小于我内容的最小宽度"。
这一长串字符的最小宽度（min-content）本身就比容器宽，所以它顶住不动， 多出来的部分只能溢出——把 Star 推出去。

情况 2：只加 flex: 1

结果和情况 1 一模一样，Star 还是在框外。

http://localhost:8123/01-html-css/day11/challenge.html
Star
.content { flex: 1; }     /* 只解决"长大"，不解决"缩小" */
.star    { flex: none; }
这就是我上一条说错的地方。
flex: 1 = 1 1 0%，它的作用是容器有剩余空间时，把剩余空间吃掉。
但情况 2 里根本没有剩余空间——是空间不够。所以它什么也没改变，Star 照样被挤出去。

情况 3：flex: 1 + min-width: 0

蓝色块不再顶破框，Star 乖乖待在框里。文本溢出部分撑开了行高。

http://localhost:8123/01-html-css/day11/challenge.html
Star
.content { flex: 1; min-width: 0; }
.star    { flex: none; }
min-width: 0 才是关键。
它把"最小不能小于内容宽度"这条限制去掉了，于是 content 可以缩到比内容更窄， 空间不够时大家一起缩，Star 就保住了位置。

那 flex: 1 到底什么时候有用？

看这个：容器很宽，内容很短。

没有 flex: 1 —— 蓝色块只有内容那么宽，中间的空白露出来了。

frontend-study
Star

有 flex: 1 —— 蓝色块撑满，Star 被推到最右。整个布局稳了。

一句话总结

  • flex: 1 —— 管「有剩余空间时，我占多少」（防留白）
  • min-width: 0 —— 管「空间不够时，我能不能缩」（防挤爆）
  • 两条一起写，布局才在宽屏和窄屏下都稳
为什么很多人只写 flex: 1 也没事？
因为绝大多数文字中间有空格或能换行，min-content 很小，默认就能缩。 只有遇到长 URL、长英文单词、white-space: nowrap 这类"不可断"的内容， min-width: 0 才显出必要性。
平时加上它，是花一个词买一份保险。
