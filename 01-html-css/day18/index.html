类名问题
project1 / project1-1数字后缀，说不清关系和身份
content1 / hero-1同上，而且"content"太笼统

你现在这个页面只有 6 个区块、300 行。等到毕设的 18 个页面、 每个页面十几个组件时，content1 这种名字会让你每周多花两小时找代码。

二、BEM 是什么

BEM = Block（块）+ Element（元素）+ Modifier（修饰符）。 一种类名命名约定，核心目的只有一个：看着类名就知道它属于谁。

概念是什么写法例子
块 Block 独立组件，能单独拿出去用 普通单词 card、btn、hero
元素 Element 块的一部分，离开块没有意义 块名 + __ + 元素名 card__title、card__desc
修饰符 Modifier 同一个块的变体 块名 + -- + 变体名 card--featured、btn--primary
记法：双下划线 __ 表示"里面的一部分"，双连字符 -- 表示"另一种样子"。
一个连字符 - 是单词连接符，比如 project-card 是一个名字，不是层级。

学习站点

左边普通卡，右边加了 card--featured 修饰符

<div class="card">
  <h3 class="card__title">学习站点</h3>
  <p class="card__desc">...</p>
  <ul class="card__tags">
    <li class="card__tag">HTML</li>

<!-- 变体：加一个修饰符类，不动结构 -->
<div class="card card--featured"> ... </div>

注意：元素类名里重复了块名（card__title 而不是 title）。 看起来啰嗦，但这正是它的价值——在任何文件里看到 card__title，你立刻知道它属于卡片。

四、七条规则

  1. 块名说"是什么"，不说"在哪"。
    ✅ nav、hero、project-card
    ❌ top-left、left-column（位置会变）
  2. 元素只用一层。
    ✅ card__title
    ❌ card__header__title（第二层没有意义，BEM 不允许）
  3. 元素不能脱离块单独用。
    card__title 必须出现在 .card 里面。如果某块内容能独立存在，它应该是一个新的块。
  4. 修饰符只改变外观或状态，不改变结构。
    ✅ btn--primary、card--featured
    ❌ card--has-three-columns（那是结构调整，该换组件）
  5. 全小写 + 连字符。
    不用下划线（和 __ 冲突）、不用驼峰、不用中文。
  6. 不用数字后缀。
    project1 / project2 如果只是"两个不同的项目"， 那它们根本就是同一个块的两个实例，都叫 card 就行。
  7. CSS 里不用写父子选择器。
    ❌ .card .card__title { }（多余，类名已经说清了归属）
    ✅ .card__title { }

五、三种常见反例

反例 1：用修饰符描述样式
card--blue-background、text--big-red
换主题时"blue"变成绿色，名字就成了谎话。修饰符要描述用途： card--featured（推荐）、card--disabled（已禁用）。
反例 2：三层嵌套
card__header__title、nav__list__item__link
BEM 规定元素只有一层。真实场景的处理办法： nav__link（跳过中间的 list/item），或者把 item 提升成独立的块。
反例 3：块名带位置或标签名
div-wrapper、left-side、p-text
标签会换（div 改 section），位置会变（响应式重排）。

七、BEM 的代价，以及现在还要不要学

代价很实在：

  • 类名变长（project-card__title vs title）
  • 写 HTML 时要反复敲块名
  • 改块名等于全文件重命名

现在的替代方案：

方案怎么解决命名冲突
Vue <style scoped>编译时自动加唯一属性，样式只作用在本组件
CSS Modules类名编译成哈希，如 card__title_a3f9
Tailwind不要类名，直接堆原子类

那 BEM 还要学吗？要，但要分清学的是什么：

  1. 学的是"命名要表意"这个习惯。 这个习惯在 Vue 里一样适用——scoped 只解决冲突，不解决"content1 到底指什么"。
  2. 你要能看懂别人的代码。大量开源项目和公司老项目用 BEM， 看到 site-header__links--compact 得能立刻读懂。
  3. 你的毕设会用到 Element Plus + Vue。组件库自己有命名体系， 但你写的业务组件仍然要起名字，el-table 的样式覆盖也需要精确的选择器。
所以这一课的真实目标不是"以后都写 BEM"，而是：
看到 project1-1 这类名字时，能意识到它三个月后是个麻烦， 并且知道有成熟的办法避免。

八、作业

重构 personal/index.html 的类名。改 HTML，同步改 CSS。

  1. 先列清单：把现在所有类名写下来，对着上面的对照表决定每个改成什么。 改之前先决定，不要边改边想。
  2. 按块分组改：一次改一个块（先 header，再 hero，再 skills，最后 projects）， 改完刷新确认不变形，再进行下一个。
  3. 删掉重复的类：link-btn btn 只留一个；link u-link 只留一个。
  4. 数字后缀全部消失：project1、project1-1、content1、 hero-1 不能再出现。
  5. 检查 CSS 里有没有多余的父子选择器：比如 .card .card__title， 有就删成 .card__title。
  6. 回答（写在文件末尾注释里）：为什么 card__title 要在类名里 重复一次 card？不重复（直接叫 title）会有什么问题？
验收标准：页面外观零变化。
和 CSS 变量那一课一样——重构的唯一合格证明是"看起来一模一样"。 我用浏览器对比改前改后的关键尺寸，你不用自己截图。
