一、标题的层级

h1 到 h6 不是六个字号，是六级目录。搜索引擎和屏幕阅读器靠它 理解页面结构：h1 是书名，h2 是章，h3 是节。所以有两个规矩：

  1. 一个页面只写一个 h1。
  2. 不能跳级。h1 下面直接出现 h4，等于书里从第一章跳到第四节， 中间的逻辑断了。

为什么跳级是问题

因为阅读器用户会按标题级别跳读页面。层级一乱，他听到的顺序就是乱的。 这属于无障碍（accessibility，常缩写为 a11y）问题，不是洁癖。

写法 结果
h1 → h2 → h3 正确
h1 → h4 层级断了，错误
三个 h1 页面有三个"书名"，错误

二、段落与换行

p 是段落，不是"一行"。浏览器会自动在段落之间留出间距， 你不需要手动空行。

br 是"换行"，只在确实需要断行的地方用——比如地址、诗歌。

三、列表的三种

ul（无序列表）
顺序不重要时用。比如"我装了哪些软件"。
ol（有序列表）
顺序重要时用。比如"操作步骤"、"排行榜"。
dl（定义列表）
词条配解释时用。比如你现在看的这一段。

嵌套：列表里放列表

子列表必须写在父级的 li 内部，不能直接挂在 ul 下面：

  • 前端
    • HTML
    • CSS
    • JavaScript
  • 后端

四、链接

链接有四种常见类型，各自的写法不同：

  • 页内锚点：href="#heading"，跳到本页的某个 id。
  • 相对路径：href="../day1/index.html"，跳到本项目里的另一个文件。
  • 绝对地址：href="https://example.com"，跳到别的网站。
  • 邮件：href="mailto:maijunxi6@gmail.com"，点了会打开邮件客户端。

链接文字要能独立看懂

屏幕阅读器会把页面上所有链接单独列出来给用户听。如果全是"点击这里"， 用户听到的是"点击这里、点击这里、点击这里"，完全不知道通向哪。

新窗口打开的安全问题

用 target="_blank" 在新标签页打开时，要同时写 rel="noopener"。 否则新页面可以通过 window.opener 反过来操纵你这个页面——这是真实存在的 钓鱼手法，不是理论风险。

五、图片

alt 到底该怎么写

alt 不是"图片描述"，是"图片不存在时，这段话能不能替代它"。

  • 信息性图片：写清它传达的信息。例：alt="2026 年前端春招时间轴"
  • 装饰性图片：写空，alt=""，让屏幕阅读器直接跳过。
  • 不要写：alt="图片"、"一张图"——等于没写。

为什么要写宽高

浏览器默认不知道图片会占多大位置，图片加载完才撑开页面，导致内容 突然往下跳。写死 width 和 height 后，浏览器提前占好位置，页面就不会抖。 这个指标在性能评估里叫 CLS（累积布局偏移）。
