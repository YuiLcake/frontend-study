第 19 天：部署上线

本地能跑不算完，别人能打开才算。

一、部署到底是什么

你现在双击 personal/index.html 能看到页面，是因为浏览器读了你硬盘上的文件。 别人打不开，因为那是你的硬盘。

部署就是：把这些文件放到一台连在公网上的服务器里，让别人也能访问。

阶段文件在哪谁能看
本地开发你的电脑只有你
已推送GitHub 仓库能看代码，但看不到渲染效果
已部署托管服务的服务器任何人打开链接都能看到
一个常见误解：以为"推到 GitHub 就等于上线了"。
不对。GitHub 存的是源码，它默认只给你看代码。 想让它当网站服务器用，必须单独开启 GitHub Pages 这个功能。

二、三种免费静态托管

服务网址形式特点国内访问
GitHub Pages yuilcake.github.io 和 GitHub 仓库绑定，无需注册新账号 一般可用，偶尔慢
Vercel 项目名.vercel.app 连接 GitHub 自动部署，支持构建和自定义域名 需要代理
Netlify 项目名.netlify.app 拖拽文件夹就能发布，也可以连 Git 需要代理

三者都是免费的，都能满足"作品页能被打开"的需求。 选哪个不重要，重要的是理解部署这件事本身——文件从哪来、放到哪、用什么地址访问。

今天用 GitHub Pages 的用户站点

GitHub Pages 有两种：

类型仓库名要求网址
用户站点 必须是 你的用户名.github.io https://你的用户名.github.io/（根路径）
项目站点 任意仓库名 https://你的用户名.github.io/仓库名/（子路径）

个人主页适合用用户站点：地址干净，就是 https://yuilcake.github.io/， 写在简历上比 /frontend-study/personal/ 好看得多，而且不用注册新账号。

三、部署后最容易坏的东西：路径

这是"本地打开一切正常，线上打开图片全裂、样式全丢"的头号原因。

三种写法，三种命运

写法浏览器理解为用户站点能用吗
<img src="img/a.jpg"> 当前页面所在目录 + img/a.jpg 能用（相对路径）
<img src="./img/a.jpg"> 同上，./ 表示"当前目录" 能用
<img src="/img/a.jpg"> 域名根目录 + img/a.jpg 用户站点能用；项目站点会裂
为什么 / 开头会裂：
/img/a.jpg 里的 / 指的是域名的根，不是"当前文件夹"。
用户站点：yuilcake.github.io/img/a.jpg ✓
项目站点：yuilcake.github.io/frontend-study/img/a.jpg ← 但你的文件在 .../frontend-study/personal/img/a.jpg，路径少了一层 → 404
结论：站内资源一律用相对路径。
img/a.jpg、./index.html、../about.html—— 不管部署到哪个地址、哪个子目录，都不会错。

顺便检查大小写

Windows 的文件系统不区分大小写（Img 和 img 是同一个文件夹）， 但 Linux 服务器区分。本地能加载、线上 404，很多时候就是这个原因。

规则：文件名和路径全部小写，用连字符不用空格。你现在 img/touxiang.jpg 是对的。

四、今天的操作步骤

  1. 新建仓库，名字必须是 YuiLcake.github.io（大小写不敏感，但习惯这样写）， 选 Public，不要勾选 README / .gitignore / license。 勾了会让第一次推送失败，因为远端已经有提交了。
  2. 把个人主页的文件放进去：index.html 和 img/ 目录。 用 git clone 下来，复制进去，再提交推送。不要用网页上传，那样学不到东西。
  3. 开启 Pages：仓库 → Settings → Pages → Source 选 main 分支、/ (root) 目录。
  4. 等 1–3 分钟，然后访问 https://yuilcake.github.io/。 第一次可能显示 404，是构建还没完成，等一会儿刷新。
  5. 验证：图片能显示吗？样式对吗？手机尺寸下正常吗？

五、上线后要验的五件事

检查怎么验
页面能打开访问根网址，看到内容而不是 404
样式正常深色背景出来了 = CSS 加载成功
图片显示头像没裂开 = 路径正确
链接可点GitHub / 邮箱链接能跳转
手机可用DevTools 切 375px，或直接用手机打开
用手机亲自打开一次。这是唯一能验证"真的上线了"的方式—— 用电脑访问可能读到缓存，而手机没访问过，一定是新鲜的。

六、四种常见故障

现象原因怎么修
打开是 404 Pages 还没构建完，或 Source 没选对 等 3 分钟；检查 Settings → Pages 的分支和目录
页面一片白，没有样式 CSS 用了 / 开头的绝对路径 改成相对路径
图片裂开 路径错、大小写不一致、文件没推上去 F12 看 Network 里图片请求是不是 404
改了代码线上没变 浏览器缓存，或还没重新构建 Ctrl+F5 强刷；去 Actions 看部署状态

排查顺序固定：F12 → Network → 看哪个请求是红色的。 红色的那个就是问题所在，比猜快得多。

七、这一步的意义

做完之后你会有一样以前没有的东西：一个能被任何人打开的网址，里面是你自己写的页面。

这意味着：

  • 简历上可以写"个人主页：yuilcake.github.io"
  • 面试时可以直接发链接，不用发压缩包
  • 毕设演示可以给别人一个网址，而不是"我电脑上能跑"
"我电脑上能跑"是学生项目的典型状态。
"打开这个链接"是交付的状态。今天这一步跨过去，你的东西性质就不一样了。
