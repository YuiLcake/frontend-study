W3 Day4 · 个人主页 v1

今天不学新东西。把这一周的 Grid、CSS 变量、响应式，合成一个真正的作品。

一、为什么值得认真做

你现在有两个"作品"：学习站点（记录用）和毕设（还没开始）。 而面试官第一眼看到的是你的 GitHub 头像和主页。

个人主页的作用不是"好看"，是三件事：

  • 三十秒内说清你是谁——名字、方向、能做什么
  • 给作品一个入口——点一下就能看到你的项目
  • 证明你会写前端——页面本身就是证据
最后一个最重要。简历上写"熟悉 CSS 布局"，不如让对方打开一个你自己排的页面。 这张页面会被反复看，值得花一天。

二、要写的内容（五个区块）

区块写什么长度

项目 2 张卡片：学习站点（线上地址）+ 毕设（一句话+技术栈） 每张 3 行

文案怎么写才不假

别写这些：
「热爱技术，善于沟通，具有较强的学习能力和团队协作精神」
—— 每个应届生都这么写，等于没写。

写这些：具体、可验证、有数字。

❌ 空话✅ 具体
热爱前端开发 2026 年 10 月起系统学习前端，每天 4–6 小时，已完成 15 天 CSS 学习并上线练习站点
熟悉 CSS 布局 能独立复刻真实站点组件，掌握 Flexbox、Grid、CSS 变量与响应式适配
有项目经验 毕业设计：校园活动报名管理系统（Vue 3 + FastAPI + MySQL），2027 年 1 月进入开发

一个判断标准：这句话能不能被第三个人验证？不能验证的，删掉。

四、技术要求（四条硬指标）

  1. 用 CSS 变量：颜色、间距、字号全部走 :root 令牌， 不许出现硬编码的 #fff、16px。 验收：改 :root 里一个颜色，整页跟着变。
  2. 页面骨架用 Grid：整页用 grid-template-areas 画出 header / hero / about / skills / projects / footer。
  3. 移动端优先：默认写手机布局，用 min-width 往宽屏加。 最多两条媒体查询。
  4. 三个宽度无横向滚动条：375px / 768px / 1280px。
不许做的事：不引入任何框架（Bootstrap、Tailwind 都不行）、不用 position: absolute 排主布局、 不复制别人的模板。这页必须每一行都是你自己排出来的。

五、实现顺序（别跳步）

  1. 写文案（30 分钟）：五个区块的文字先全部写在 HTML 里，不要样式。 文案卡住会拖一整天，先解决它。
  2. 搭令牌（15 分钟）：:root 定义颜色 5–6 个、间距 5 个、字号 4 个、圆角 2 个。 选一套你喜欢的主色，整页只用它和它的深浅变化。
  3. 画骨架（30 分钟）：整页 Grid + areas 图，先不写任何细节样式。 刷新看到六个方块排好就算过。
  4. 填细节（60–90 分钟）：逐个区块调整字号、间距、边框、按钮。 一次只改一个区块，改完刷新看一眼。
  5. 适配（30 分钟）：手机版对照线框图调整。
  6. 自检（15 分钟）：三个宽度、四项验收。

合计约 4 小时。做不完就到第 4 步停下，剩下的明天继续。

六、验收标准

项标准
结构语义标签（header / main / section / footer），无多余的 div 套娃
令牌全文没有硬编码颜色值
布局整页由一张 grid-template-areas 图描述
响应式375 / 768 / 1280 无横向滚动条、无重叠、字能直接读
文案每句话都能被验证，没有"热爱""善于"这类空话
可访问性图片有 alt、链接有可读文字、标题层级 h1 → h2 不跳级

交付：personal/index.html（样式写在文件内 <style> 里）。

七、预告三个坑

  • 整页用 Grid 时，body 要不要当容器？ 可以，但要注意 body 上的 max-width 会限制整页宽度。 更常见的是给一个 .page 包裹层当容器。
  • hero 区域两栏在手机上要换顺序：桌面是"文字在左、头像在右"，手机是"文字在上、头像在下"。 用 grid-template-areas 换图就行，不用改 HTML。
  • 技能标签用 flex-wrap，不要用 grid：标签宽度不一致，grid 会排成整齐的格子，反而难看。
