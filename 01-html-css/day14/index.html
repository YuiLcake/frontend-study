第 14 天：响应式三件套

viewport、移动端优先、媒体查询。学完这一课，你的站点在手机上才算能用。

一、同一份代码，所有屏幕

同一套 HTML/CSS，要同时在下面这些宽度上正常工作：

设备 CSS 宽度
手机（竖） 360 – 430px
手机（横）/ 小平板 568 – 768px
平板 768 – 1024px
笔记本 1280 – 1536px
外接显示器 1920px 以上

差 5 倍以上。写死一个尺寸，必然有一类是坏的。

注意这里说的是 CSS 宽度——不是物理分辨率。手机的物理像素有 1080 甚至 1440， 但 CSS 宽度只有 360–430。这个换算就是下面要说的 viewport。

二、第 0 步：viewport meta 标签

这一行没有的话，下面所有努力全部白费：

<meta name="viewport" content="width=device-width, initial-scale=1.0">

不加会发生什么：

手机浏览器默认按 980px 的"虚拟宽度"来渲染页面，然后把整张 980px 宽的图缩小塞进屏幕。 结果是：字变得极小，你得用两根手指放大才能看。

写法 效果
没有 meta 按 980px 渲染再缩小 → 字小到看不清，媒体查询也按 980px 判断
width=device-width 页面宽度 = 设备宽度 → 正常显示，媒体查询才有意义
initial-scale=1.0 初始不缩放
为什么这行会影响媒体查询：没有它时，浏览器认为自己有 980px 宽， 你的 @media (max-width: 600px) 永远不会触发——它以为屏幕有 980px 呢。
所以：媒体查询不生效，先检查这一行。

你的站点已经有这一行了（第 1 天写的），所以可以直接进下一步。

三、移动端优先：先写手机，再加宽屏

两种写法，方向相反：

/* 桌面优先：先写宽屏，再用 max-width 往回改 */
.container { grid-template-columns: repeat(3, 1fr); }
@media (max-width: 768px) { .container { grid-template-columns: 1fr; } }

/* 移动端优先：先写手机，再用 min-width 往前加 */
.container { grid-template-columns: 1fr; }
@media (min-width: 768px) { .container { grid-template-columns: repeat(3, 1fr); } }

推荐移动端优先，两个理由：

  • 手机是默认状态。手机屏幕更小、限制更多，先解决最难的情况，宽屏是"加分"。
  • 代码更少。手机版通常更简单（一列、纵向堆叠），桌面版是"增强"，用 min-width 一层层加上去，逻辑是叠加而不是覆盖。

而且现在移动流量占比普遍高于桌面，先保证手机能用是更实际的策略。

四、媒体查询语法

@media (min-width: 600px) {
  /* 屏幕宽度 ≥ 600px 时，这里面的规则生效 */
}

@media (max-width: 599px) {
  /* 屏幕宽度 ≤ 599px 时生效 */
}

@media (min-width: 600px) and (max-width: 900px) {
  /* 区间：600 到 900 之间 */
}

@media (prefers-color-scheme: dark) {
  /* 用户系统开了深色模式 */
}

五、断点怎么选：按内容，不按设备

新手最常见的做法是背设备宽度：

@media (max-width: 375px) { }  /* iPhone SE */
@media (max-width: 390px) { }  /* iPhone 14 */
@media (max-width: 414px) { }  /* iPhone Plus */

这是错的。手机型号无穷无尽，你永远列不完，而且明年就过时了。

正确做法：拖窄窗口，看到布局"开始难看"的那一刻，就是断点。

  1. 把窗口从宽往窄慢慢拖
  2. 盯住内容——什么时候文字挤成一团、卡片窄到放不下、两栏挤成一栏更舒服
  3. 那个宽度就是你的断点，写进去

这叫内容断点。因为布局坏掉的原因是"内容放不下"，跟用户拿的是 iPhone 还是小米没关系。

如果实在没头绪，可以用这组常见值起步，但一定要自己拖一遍验证： 

480px   大手机横屏
768px   平板竖屏
1024px  平板横屏 / 小笔记本
1280px  笔记本

六、能不用媒体查询就别用

媒体查询是"补救"手段。很多需求用内在响应式（你已经学过）就能解决：

需求 更好的做法
卡片能并排也能堆叠 repeat(auto-fit, minmax(240px, 1fr))
一行元素放不下就换行 flex-wrap: wrap
字号随屏幕变化 clamp(20px, 4vw, 36px)
元素随容器宽度变化 clamp() / 容器查询
流体字号演示（拖窗口看标题大小）

clamp(20px, 4vw, 36px)

clamp(最小值, 理想值, 最大值)：字号跟着视口宽度 vw 走， 但不小于 20px、不大于 36px。一行代码替代三个断点。

原则：能用内在响应式解决的，不要写断点。断点越少，维护成本越低，出 bug 的地方越少。

七、图片也要响应式

img {
  max-width: 100%;   /* 不超过容器宽度 */
  height: auto;      /* 保持比例，不拉伸 */
}

没这两条时，一张 2000px 宽的图会把整个页面撑出横向滚动条—— 而图片本身的像素宽度是死的，不会自己缩。

再进一步，用 srcset 让浏览器按屏幕选图片（手机不用下载 2000px 的大图）—— 这个等你做毕设上传封面图时再说，现在知道有这么回事就行。

八、怎么测试

  1. F12 打开 DevTools
  2. 点左上角的设备图标（或 Ctrl + Shift + M）
  3. 在顶部下拉里选机型，或者直接拖边框改宽度
  4. 重点看三个宽度：375px（手机）、768px（平板）、1280px（笔记本）

每次都要检查的四件事：

检查项 判断标准
横向滚动条 不该出现。出现了说明有元素超出视口
文字大小 不用放大就能读，正文不小于 14px
点击区域 按钮、链接不小于 44×44px（手指比鼠标粗）
内容重叠 没有元素互相压住

九、作业

在你的学习站点上做。改 docs/css/main.css。

  1. 先看现状：DevTools 切到 375px，截图看你的站点现在什么样。 大概率：卡片挤成一列、导航挤在一起、字很小。
  2. 两栏变一栏：现在 main 是 grid-template-areas: "posts side"。 用移动端优先补一条——窄屏时改成 "posts" "side" 纵向堆叠。 
    @media (max-width: 767px) {
  main { grid-template-columns: 1fr; grid-template-areas: "posts" "side"; }
}

    注意：如果你坚持移动端优先，这条应该反过来写——默认单列，min-width 时才两栏。选一种，别混用。

  3. 导航适配：窄屏时导航链接会挤成一团。用 flex-wrap: wrap 让它换行， 或者用媒体查询减小间距和字号。
  4. 图片响应式：给 img 加 max-width: 100%; height: auto;， 确认窄屏不出现横向滚动条。
  5. 记录断点理由：在 CSS 注释里写清楚——你选的每个断点，是因为什么内容放不下才定的。
验收：375px、768px、1280px 三个宽度下都不出现横向滚动条， 文字不用放大能读，没有元素重叠。
