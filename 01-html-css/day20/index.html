二、一个昨天留下的问题：你有了两份一样的文件

实测两份文件的内容哈希完全相同：

frontend-study/personal/index.html      b160b562...
YuiLcake.github.io/index.html           b160b562...   ← 一模一样

现在改哪一份？

你改的地方线上会变吗学习仓库会变吗
frontend-study/personal/不会（线上部署的是另一个仓库）会
YuiLcake.github.io/会（推送后）不会，那份逐渐变旧
这就是"两份副本"的必然结局：分叉。
今天你改了一边，明天忘了另一边，一个月后你就分不清哪份是新的。 更糟的是——你改错地方时会以为自己在改线上，等半天发现没变化，白白浪费时间。
解决原则：单一数据源（single source of truth）。
同一个东西只保留一份，其他位置指向它，而不是复制它。

三、今天怎么处理

个人主页已经独立成一个仓库了，它自己就有版本历史、有部署。 所以以 YuiLcake.github.io 为唯一源，学习仓库里那一份删掉。

步骤：

  1. 先确认两份完全一致（已经在上面验过，md5 相同）
  2. 删掉学习仓库里的副本： 
    cd ~/Desktop/frontend-study
git rm -r personal
git commit -m "chore: 个人主页已独立成仓库，删除重复副本"

    git rm 而不是直接删文件夹：它会把"删除"这个动作也记进版本历史， 以后想找回还能找回。

  3. 在学习仓库的 README 里加一行，告诉未来的自己主页在哪： 
    个人主页（独立仓库）：https://yuilcake.github.io/

为什么不删 YuiLcake.github.io 而删学习仓库那份？ 因为前者是线上正在用的，它还有部署配置。删部署源等于下线网站。

四、你的工作流从今天开始变了

以前：

改文件→刷新浏览器

现在：

改文件→本地预览→git commit→git push→等 1–2 分钟→线上验证

多出来的环节是为了让别人也能看到。但它带来一个新问题： 每次看效果都要等部署，改一个 4px 的间距也等两分钟，效率太低。

所以要做两段验证：

阶段在哪看看什么
开发中 本地 python -m http.server 像素级细节：间距、对齐、颜色
推送后 线上网址 只验"有没有坏"：能打开、样式在、图片在
本地起服务的命令（在 YuiLcake.github.io 目录里执行）： 
python -m http.server 8000
然后打开 http://localhost:8000/。 改完刷新即可，不用等部署。

五、v2 打磨清单

六个具体改动，从影响大到小：

  1. 页面标题改成有意义的
    现在是 <title>我的网页</title>。 浏览器标签页、搜索结果、别人转发链接时的预览，用的都是它。 
    <title>熙熙 · 前端开发</title>
  2. 加一句 description
    别人在微信/GitHub 分享你的链接时，下面那行小字就是它。 
    <meta name="description" content="熙熙的个人主页 · 软件工程 · 前端开发方向">
  3. hero 的「查看项目」改成按钮
    现在它是纯文字链接，而下面卡片里的是按钮——同一个动作两套样式。 
    <a href="..." class="btn btn--primary">查看项目</a>

    hero 是页面的第一视觉焦点，它的按钮应该是整页最显眼的。

  4. hero 两栏之间留白太大
    文字区到头像之间空了近 400px。给 hero__grid 的第二列改小一点， 或者给文字区加个 max-width，让整体更紧凑。
  5. 统一的间距节奏
    检查所有 gap 和 margin，是不是 4 / 8 / 12 / 16 / 24 这几个值。 出现 7px、18px、30px 这种就改掉。
  6. 移动端复查
    DevTools 切 375px，看有没有挤、有没有文字换行难看、按钮够不够大。
