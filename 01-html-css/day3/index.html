为什么要 scope

scope="col" 表示"这个表头管一整列"，scope="row" 表示"管一整行"。 屏幕阅读器读到某个单元格时，会先报出对应的表头，用户才知道 "这个 720 是星期几的"。 不写 scope 表格照样显示，但盲人用户听到的是一串没有上下文的数字。

合并单元格

colspan 横向合并（占几列），rowspan 纵向合并（占几行）。 能不合并就不合并——合并会让表格结构变复杂，也容易算错格子。

二、表单：包住所有输入控件的外壳

form 标签有两个作用：把控件圈成一组，以及决定这些数据往哪发、怎么发。

属性 作用
action 提交到哪个地址（后端接口）。不写就是提交给当前页面。
method GET 把数据拼在网址后面，POST 放在请求体里。涉及密码、文件必须 POST。

GET 和 POST 的差别现在不用记住细节，W5 学网络请求时会彻底讲清。 现在只要知道：默认是 GET，传密码必须改成 POST。

三、input 的类型不是装饰，是行为

type 决定了三件事：浏览器给什么控件、手机弹出什么键盘、要不要自带校验。

type 长什么样 额外好处
text 普通输入框 无
email 输入框 提交时自动检查格式；手机键盘带 @
password 圆点遮盖 防止旁观者看到
number 带上下箭头的数字框 手机弹数字键盘
date 日期选择器 免去手输格式错误
checkbox 方框，可多选 —
radio 圆点，一组里只能选一个 靠 name 相同来分组
file 文件选择 —
range 滑块 —
hidden 看不见 偷偷带一个值给后端（如活动 id）

用 type="text" 假装成邮箱输入框是最常见的偷懒。手机用户会遇到 没有 @ 键的键盘，等于让他在错误的键盘上打正确的字。

四、label：为什么它必须写

label 有两个作用，第二个才是真正的原因：

  1. 视觉上告诉用户这个框填什么
  2. 和输入框绑定后，点文字就能聚焦到输入框。 复选框和单选框尤其明显——点"我同意"三个字就能选中， 不用精确地点中那个小方框。

绑定方式是 for 和 id 对上号：

<label for="nick">昵称</label>
<input id="nick" type="text">

最常见的错误：用 placeholder 代替 label。

问题有三个：一开始输入，提示就消失了，用户忘了这格填什么； 屏幕阅读器对 placeholder 的支持不稳定；placeholder 的浅灰色 对比度往往不达标。 placeholder 是补充说明，不是标签。

正确做法：label 常驻显示，placeholder 只放示例。


五、按钮的三种 type（这里最容易出事）

button 不写 type 时，默认是 type="submit"。 意思是：只要它在 form 里面，点它就会提交整个表单。

type 点了会怎样 什么时候用
submit 提交表单 表单的"确定/提交"按钮
button 什么都不做，等你用 JS 绑事件 "清空"、"获取验证码"这类
reset 把所有控件恢复成初始值 很少用，误触会让人白填一遍

典型事故：表单里放了一个"清空"按钮，忘了写 type="button"。 用户点了它，表单直接提交上去了——因为默认是 submit。 这种 bug 找起来很费时间，因为代码看起来毫无问题。

经验法则：form 里的每一个 button，都显式写 type，哪怕是 submit。 写出来是为了让读代码的人不用猜。
