第 5 天：从一个页面到一个网站

昨天你做出了一个合格的首页。今天要让它变成"网站"——多个页面，互相能找到对方。

一、网站不是"一个很大的页面"

网站是一组独立的文件，每个页面都是单独的 HTML，靠链接互相指路。 浏览器一次只加载一个文件，点到哪个就加载哪个。

这里有一个隐含规则：当用户访问一个目录（比如 /docs/）时， 服务器会自动去找那个目录下的 index.html 作为默认页面。 这就是为什么首页必须叫 index.html——不是约定，是服务器的默认行为。

二、相对路径（今天最重要的一节）

先看我们站点的目录形状：

frontend-study/          ← 仓库根目录
├── docs/                ← 站点目录（GitHub Pages 认得这个名字）
│   ├── index.html       ← 首页
│   ├── about.html       ← 关于页（今天要建）
│   └── contact.html     ← 联系页（今天要建）
└── 01-html-css/         ← 前四天的练习，和站点无关
    ├── day1/
    └── day2/

三个页面在同一个文件夹里，所以互相链接的写法最简单：

要去的文件写法含义
同目录的 about.htmlhref="about.html"就在我旁边
同目录的 index.htmlhref="index.html"同上；也可以写 href="./"
子目录里的 posts/first.htmlhref="posts/first.html"往下走一层
上一级的文件href="../index.html"往上退一层，.. 就是"上一级"

为什么不用绝对路径

这两种写法在你自己电脑上能点开，但别人访问时一定失效：

href="C:\Users\麦俊熙\Desktop\frontend-study\docs\about.html"
href="file:///C:/Users/麦俊熙/Desktop/..."

第一个是你硬盘上的路径，别人的电脑没有这个目录； 第二个是"本地文件"协议，服务器上根本不存在。

相对路径跟着文件走，换机器、换服务器、换域名都能用：

href="about.html"

还有一个容易踩的：以 / 开头的路径

href="/about.html" 表示"从网站根目录开始找"。 它在你自己的顶级域名下没问题，但 GitHub Pages 的项目站点是 用户名.github.io/仓库名/，站点不在根上—— 这时 /about.html 会去找 用户名.github.io/about.html， 直接 404。

结论：项目阶段一律用相对路径，别用以 / 开头的。

三、本地能打开，线上 404 的三个原因

原因为什么本地看不出来怎么避免
大小写不一致 Windows 的文件系统不区分大小写，写 About.html 也能打开 about.html；Linux 服务器区分，直接 404 文件名全小写，链接里的名字和文件名逐个字母对齐
路径写错或漏了扩展名 浏览器不会提醒你，只会给你一个 404 页面 用 VS Code 的自动补全：输入 href=" 后会列出同目录的文件
中文文件名或空格 本地可能正常，线上会被编码成一串 %E4%B8%AD 文件名只用小写字母、数字、连字符

四、导航必须三页一致

用户在任何一页都应该能去其他任何一页。所以三个页面的 header 和 nav 要一模一样——做法是：写完首页的 header，直接复制到另外两页，不要各自手写。

还有一个细节：当前所在的页面，在导航里应该被标出来。

<nav>
  <a href="index.html">首页</a>
  <a href="about.html" aria-current="page">关于我</a>
  <a href="contact.html">联系我</a>
</nav>

aria-current="page" 是告诉屏幕阅读器"这个链接指向的就是当前页"， 用户能听出自己在哪。视觉上可以再用 CSS 加粗（W2 学）。

五、部署到底是怎么回事

部署 = 把你的文件放到一台一直开着的服务器上，让别人能通过网址访问。 我们做的是静态站点：只有 HTML/CSS/图片，没有后端程序， 所以不需要买服务器、不需要配数据库。

GitHub Pages 提供了免费托管，规则很简单：

  • 它只从仓库的两个位置取文件：根目录 或 docs 目录
  • 取到之后，你的仓库就变成了一个网站
  • 网址格式是 用户名.github.io/仓库名/
  • 每次 push 之后，它会自动重新发布，通常一两分钟内生效

这也是我们把站点文件夹改名为 docs 的原因——不是我喜欢这个名字， 是 GitHub Pages 只认这两个位置。

六、今天的作业

  1. 建 about.html：复制 docs/index.html，另存为 about.html，然后改三处：<title>、 <h1>、正文内容（写你的学习目标、为什么学前端）。 日志列表那一段删掉，换成 2-3 段关于你自己的介绍。
  2. 建 contact.html：同样复制，改成联系方式页。 内容包含：邮箱（mailto 链接）、GitHub 主页地址。
  3. 三页互链：三个页面的 nav 都写成同样的三个相对路径链接： index.html、about.html、contact.html。 点遍九个方向（每页点另外两个链接），确认都能到达。
  4. 标记当前页：每个页面里，把指向自己的那个链接加上 aria-current="page"。
  5. 大纲自查：三个页面各检查一遍——是不是只有一个 h1、 h2 层级是否一致、标题有没有跳级。把结论写在文件末尾的注释里。

做完这五条，W1 就结束了。我们会在周末复盘这一周， 然后进入 W2——CSS，把这三个页面真正变好看。
